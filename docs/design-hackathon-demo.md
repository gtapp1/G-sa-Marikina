## Problem Statement

G sa Marikina is being submitted as a hackathon project. The platform is functional (browse, map, search, auth, reviews, business submission) but needs two standout features that make judges stop scrolling and lean in during a 2-3 minute demo.

## What Makes This Cool

Two features that combine geographic intelligence with conversational AI, scoped specifically to hyperlocal food discovery in Marikina City:

1. **Barangay Polygon Map** — Select a barangay and its real geographic boundary lights up on the map, camera flies to fit it, and only listings within that barangay are shown. Demonstrates geographic awareness that goes beyond "pins on a map."

2. **AI Food Concierge** — A floating chat widget where users ask questions in Taglish ("Saan may masarap na milk tea sa Concepcion?") and get real answers grounded in actual platform data. Not a generic chatbot — it only knows about real Marikina food spots on the platform.

## Constraints

- Solo developer, tight timeline (days, not weeks)
- Gemini free tier API for the LLM (sufficient for demo, not production)
- 7 static listings fit entirely in Gemini's context window (no vector DB needed)
- Must work on mobile (judges may test on phones)
- GeoJSON polygon accuracy depends on available OpenStreetMap data for Marikina barangays

## Premises

1. Both features need to be demo-ready (visually impressive, works in a live walkthrough) but not production-hardened.
2. The barangay boundaries need GeoJSON polygon data for all 16 Marikina barangays — this data needs to be sourced from OSM or manually traced.
3. Gemini free tier API key for the LLM, just for demonstration purposes.
4. The chatbot only queries the 7 existing static listings (from `src/data/listings.ts`), not the Supabase database. This simplifies the pipeline.
5. Timeline is tight — build in days, not weeks.

## Approaches Considered

### Approach A: GeoJSON Boundary Overlay (Map) — CHOSEN
Source/create GeoJSON polygons for all 16 barangays. On select, render a fill+outline layer on MapLibre, fly camera to fit bounds, filter sidebar/pins to that barangay.
- Pros: Visually stunning, MapLibre handles GeoJSON natively, reusable
- Cons: Sourcing accurate GeoJSON takes effort, some borders may be approximate

### Approach B: Approximate Circle Zones (Map) — REJECTED
Use center points with radius circles instead of true polygons. Simpler but looks generic.

### Approach A: Gemini RAG with System Prompt (Chatbot) — CHOSEN
Next.js API route calls Gemini with system prompt containing all listings data as context. No vector DB needed. Floating chat widget on frontend.
- Pros: No vector DB needed, Gemini handles Taglish, streaming responses, simple architecture
- Cons: Free tier rate limits (fine for demo), quality depends on prompt engineering

### Approach B: Vercel AI SDK + Gemini (Chatbot) — REJECTED
Extra dependency layer. Overkill for 7 listings in context window.

## Recommended Approach

Both Approach A selections. GeoJSON polygons for visual impact + direct Gemini API for simplicity.

## Implementation Plan

### Feature 1: Barangay Polygon Map

#### Data: GeoJSON Boundaries

Source barangay boundary polygons. Options in priority order:
1. **OSM Overpass API** — Query OpenStreetMap for Marikina barangay admin boundaries (admin_level=10 in PH)
2. **Manual GeoJSON from geojson.io** — Trace boundaries from satellite imagery if OSM data is incomplete
3. **Philippine Statistics Authority shapefiles** — Convert to GeoJSON if available

Store as: `src/data/barangay-boundaries.json` (single GeoJSON FeatureCollection)

Each feature should have:
```json
{
  "type": "Feature",
  "properties": {
    "name": "Concepcion Dos",
    "id": "concepcion-dos"
  },
  "geometry": {
    "type": "Polygon",
    "coordinates": [[[lng, lat], ...]]
  }
}
```

#### UI: Barangay Selector + Map Integration

**Components to modify/create:**
- `src/components/food-map.tsx` — Add GeoJSON source + fill/line layers, barangay select dropdown
- `src/components/barangay-selector.tsx` — Dropdown or pill bar listing all 16 barangays

**Behavior:**
1. User selects a barangay from the dropdown/pill bar above or beside the map
2. Map adds a semi-transparent fill layer (orange at 20% opacity) over the selected barangay polygon
3. Map adds a solid stroke layer (orange, 2-3px) outlining the boundary
4. Camera does `fitBounds()` to the polygon's bounding box with padding
5. Sidebar filters to only show listings in that barangay
6. Map pins outside the barangay become dimmed or hidden
7. "Clear" button resets to show all of Marikina

**MapLibre layers needed:**
```
Source: "barangay-boundaries" (GeoJSON FeatureCollection)
Layer: "barangay-fill" (type: fill, paint: fill-color orange, fill-opacity 0.15)
Layer: "barangay-outline" (type: line, paint: line-color orange, line-width 2.5)
Filter: ["==", ["get", "name"], selectedBarangay]
```

**Fallback scope:** If fewer than 10 barangays have usable OSM polygon data, reduce scope to only the barangays where listings exist (Malanday, Concepcion Uno, Sta. Elena, Industrial Valley, San Roque, Barangka). Demo only needs 2-3 working polygons to impress judges.

**Loading behavior:** GeoJSON is bundled statically (renders instantly). Show a skeleton spinner over the map area until OSM raster tiles load. Pins outside the selected barangay are hidden (not dimmed — simpler, cleaner for demo).

**Demo moment:** Judge clicks "Sta. Elena" → map smoothly zooms and outlines the area → only Tea Kayo and Aling Beb's appear. Geographic intelligence in one click.

### Feature 2: AI Food Concierge Chatbot

#### Backend: Next.js API Route

**File:** `src/app/api/chat/route.ts`

**Architecture:**
```
User message → API route → Build prompt with listings context → Call Gemini → Stream response back
```

**System prompt structure:**
```
You are "G!", the AI food concierge for G sa Marikina — a local food discovery 
platform for Marikina City, Philippines.

RULES:
- Only answer questions about food, restaurants, and the platform
- Only reference listings that exist in the data below
- Respond in the same language the user uses (Tagalog, English, or Taglish)
- If you can't find a match, say so and suggest browsing the platform
- Never invent or hallucinate listings
- Keep responses concise (2-4 sentences max)
- Include the listing link when recommending a spot: /[slug]

PLATFORM DATA:
[...full listings array serialized as JSON or structured text...]

PLATFORM FEATURES:
- Browse by category at /categories
- View map at /map  
- Search at /search
- Business owners can submit at /for-businesses/new
- Users can leave reviews on any listing page
```

**Gemini API call:**
- Model: `gemini-1.5-flash` (fast, free tier generous)
- Temperature: 0.7 (conversational but grounded)
- Max tokens: 300 (keep responses short for chat)
- Streaming: Yes — use Web Streams API (ReadableStream + TextDecoder) in the fetch response, returning `new Response(stream)` from the Next.js route handler

**Error handling:**
- Gemini 429 (rate limit): Show "G! is thinking... try again in a moment" and disable send button for 5 seconds
- Gemini timeout (>10s): Show "G! couldn't reach the kitchen. Try again?"
- Empty response: Show "Hindi ko sure yan — try browsing /search instead!"
- Pre-demo: verify rate limit by simulating 5 rapid queries. If tight, add in-memory throttle or upgrade to pay-as-you-go ($0 for low volume)

**Env var needed:** `GOOGLE_GEMINI_API_KEY`

#### Frontend: Chat Widget

**File:** `src/components/chat-widget.tsx`

**Design:**
- Floating button (bottom-right corner, 56px circle, orange with chat icon)
- Click opens a 360px × 480px chat panel (slides up on mobile, pops up on desktop)
- Header: "G! Food Concierge" with close button
- Message area: scrollable, user messages right-aligned, bot messages left-aligned
- Input: text field + send button at bottom
- Typing indicator (pulsing dots) while waiting for response
- Links in bot responses are clickable (navigate to listing pages)

**State management:**
- `messages[]` — array of {role, content, timestamp}
- `isOpen` — widget expanded or collapsed
- `isLoading` — waiting for Gemini response
- Persist nothing — fresh conversation each page load (demo simplicity)

**Mobile behavior:**
- Widget button smaller on mobile (48px)
- Chat panel goes full-width on mobile, half-height overlay
- Input uses `enterkeyhint="send"` for mobile keyboard

**Suggested starter messages (shown when empty):**
- "Saan may masarap na cookies?"
- "What's the highest rated spot?"
- "Anong mura na food sa Industrial Valley?"

#### Integration

- Add `<ChatWidget />` to the root layout (`src/app/layout.tsx`) so it's available on every page
- Chat widget renders client-side only (uses state, calls API)
- No auth required to use the chatbot (public feature)

## Success Criteria

1. **Map:** A judge clicks a barangay name → sees the boundary animate on the map → sees filtered results. Takes under 2 seconds.
2. **Chatbot:** A judge types "Saan may milk tea?" in Taglish → gets a real answer pointing to Tea Kayo Milktea with a link → clicks through to the listing. Takes under 3 seconds.
3. **Both features work on mobile and desktop.**
4. **Neither feature crashes or shows errors during a live demo.**
